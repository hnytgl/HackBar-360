# HackBar-360 2.5.0 · Request Lab

## 安装：解决“清单文件缺失或不可读取”

1. 将 `HackBar-360-v2.5.0.zip` **解压到一个独立文件夹**，例如 `D:\hack\HackBar-360-v2.5.0`。
2. 打开这个文件夹，应立即看到 `manifest.json`、`background.js`、`theme`、`popup`、`icons`、`help`。**manifest.json 在 ZIP 根目录，没有多套一层 HackBar 文件夹。**
3. 在 360 浏览器的扩展管理页面开启开发者模式，选择“加载已解压的扩展程序”，选中 **包含 manifest.json 的文件夹**。
4. 目标页面使用 Chromium / 极速模式，按 F12，选择 HackBar 标签；看不到时检查开发者工具的 `»` 折叠菜单。更新扩展后关闭并重新打开 F12。
5. 也可点击扩展图标 → “打开独立调试窗口”。独立窗口可以发送请求，但“从 Network 选择请求”需要 F12 上下文。

不要在解压前选择 ZIP 的父目录，也不要直接双击 manifest.json。如果浏览器明确提示 Manifest V2 不受支持，这和“找不到清单”是两个不同问题。本包延续原始源码的 Manifest V2，目标是仍允许加载 MV2 的 360 Chromium 内核；不同 360 版本和企业策略需实际确认。

## 请求调试

- 布局：顶部横向菜单，URL 输入区，左侧 POST 开关 / 方法 / 正文，右侧逐行编辑请求头。支持深浅主题和窄窗口。
- 方法：GET、POST、PUT、PATCH、DELETE、HEAD、OPTIONS。POST 开关会同步方法；GET / HEAD 不发送正文。
- JSON 正文先校验，但保留用户原始文本；form 正文按原样发送（重复键、空值、`+` 和 `%xx` 不会被重建）；raw 可填写自定义 Content-Type。
- 未提供 Content-Type 时按正文类型补齐；已启用的自定义头优先。重复头、非法头名、换行、过大正文会明确拒绝。
- EXECUTE 或 Ctrl+Enter 发送；取消按钮中止当前请求。默认超时 30 秒，可设置 1–120 秒。请求不会导航被检查页面。
- 响应显示状态码、耗时、读取字节数、JSON / 原始文本 / 可见响应头。4xx / 5xx 保留正文。HTML 和脚本以纯文本显示，不执行。
- LOAD 读取被检查页面 URL。TEST → 从 Network 选择请求，可回填 DevTools 已捕获的 URL、方法、正文和请求头；浏览器控制的头默认不启用。
- 编辑器的脱敏草稿会自动保存。恢复后如出现 `[REDACTED]`，请补入真实值再发送；含占位符的请求会被拒绝。

## 历史、对比和笔记

- 历史保存在扩展本地存储中，始终脱敏，最近 50 条，总体约 3 MiB；单条历史的请求体和响应体各保留前 12,000 字符。可以搜索、回填、查看、删除或清空。
- 历史回填不会自动发送。已脱敏的凭据需要重新填写。当前实时响应保留在内存中，关闭面板后不再保留其原始版本。
- 响应或历史可设为基线 A，选择当前响应 B 后比较状态、耗时、响应头和正文。JSON 会先格式化，正文按行号比较；每部分最多检查前 2,000 行、显示 200 处差异。这不是语义 JSON diff；插入一行后可能出现连续差异。
- 测试笔记需要点击“保存笔记”，保存时脱敏；导出前也会保存笔记。未保存的修改有提示。
- HTML、Markdown、JSON 报告包含当前结果、全部已保留历史、已保存笔记和已生成的对比结果，始终脱敏。对比基线仅在当前面板内存中保存。

## 脱敏范围与限制

默认脱敏显示可切换为原始视图。历史、草稿、笔记和报告没有关闭脱敏的选项。处理常见认证 / Cookie 头、password / secret / token / session / API Key 字段、URL 查询参数和账号密码、JWT、邮箱和中国大陆手机号。

自动脱敏属于启发式处理，无法保证识别任意秘密；未知字段、Base64 / 其他编码、URL 路径、自由文本、文件内容中的秘密可能遗漏。分享前需要人工复核。当前响应取消“脱敏显示”后，复制的也是原始视图。扩展不包含遥测、许可证联网验证、远程脚本或云端同步；它只会向用户主动发送的目标发起调试请求。

## 浏览器网络限制

- 这是浏览器 Fetch 调试器，不是原始 TCP / HTTP 报文重放器。Host、Cookie、Referer、User-Agent、Origin、Content-Length、Connection、Accept-Encoding、`Sec-*`、`Proxy-*` 等不能手工指定；启用这些头会报错，不会假装发送成功。普通自定义头（如 Authorization、X-API-Key、X-Test）可发送。
- Cookie 通过“携带浏览器凭据”交由浏览器管理，默认关闭。是否发送取决于 SameSite、第三方 Cookie、站点权限及浏览器策略；无法手工覆盖 Cookie 或其他受限头。此限制也适用于旧版 User-Agent / Referer / Cookie 输入功能。
- 默认不自动跟随重定向，3xx 跳转会以网络失败提示，避免把认证信息自动带向其他地址；Fetch 无法提供被阻止重定向的完整响应。
- 不绕过 TLS 证书、CORS / 企业策略或浏览器权限。不支持 TRACE / CONNECT、WebSocket、文件上传重建、multipart 边界自动重建、二进制预览或流式 UI。正文按 UTF-8 解码；二进制或其他字符集可能显示乱码。
- 请求体最大 1 MiB，实时响应最多读取 2 MiB（达到上限会标注）；历史正文另有截断。字节数指读取的解码前数据，非传输层大小，耗时包含读取响应正文。可见响应头受 Fetch 限制，例如 Set-Cookie 不会显示。
- 不会持续抓取页面流量或全局改写页面请求头。Network 只在手工选择时读取已有 DevTools 记录。SSRF / SSTI / LFI / SHELL 菜单仅插入或转换文本，不执行扫描或命令。

## 原 HackBar 文本工具

保留 MD5、SHA-1、SHA-256、ROT13、URL / Base64 / Hex 编解码、JSON 格式化、大小写、MySQL / MSSQL / Oracle 字符表达式、UNION SELECT、内联注释、数据库信息和 CONVERT 表达式、XSS 字符码 / HTML 实体和 alert 测试文本。补充 UTF-8 支持、HTML 转义、空白清理、反斜杠和 Shell 引号处理。先选中输入框内的文字；未选中则处理整个输入框。SPLIT 将 `?` / `&` 拆行，发送 URL 时会移除换行。

SQL / 模板 / XSS 菜单是手工文本工具；并不判断目标是否存在漏洞，也不提供扫描结果。
